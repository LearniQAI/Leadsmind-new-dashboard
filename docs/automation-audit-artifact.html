The Workflow Builder, verified line by line

A ground-truth account of LeadsMind's automation engine — what fires, what's a stub, what broke under real load and got fixed, and how it stacks up against Systeme.io and GoHighLevel.

LeadsMind's Workflow Builder is the "when X happens, do Y" system behind the CRM — the same idea as a Systeme.io or GoHighLevel automation. A trigger (a contact enrolls in a course, a payment lands, a tag gets added) starts a workflow; the workflow runs a sequence of actions (send an email, tag a contact, move a deal, enroll someone in a course) and can branch down different paths based on conditions you set. It's live in production today, with a visual editor your team already builds these in — no code required.

Branching — real conditional routing, not a diagram

A Route step lets you define named branches (e.g. "Hot Leads" vs. "Everyone Else") with conditions like equals, contains, exists, greater/less than, or between a range. The first branch whose conditions all match wins; if none match, it falls back to a default. A Split step handles true A/B testing, deterministically keeping the same contact in the same variant every time.

The editor your team uses today

  • A grouped trigger picker, a step list with add/remove/reorder

  • Live entity pickers — tags, pipeline stages, team members, courses, and bundles are pulled from your workspace's real Supabase data, not hardcoded lists or free text
  • A dedicated branch/route editor and split-test editor
02

Evidence of production-grade engineering

A demo proves an automation can run once. What proves it holds up is what breaks when two things happen to the same contact at once, or when a real anonymous visitor — not a test account — hits a public form. We deliberately tested those conditions and fixed four real issues before they reached a client:

  1. Concurrency gate fix — a contact finishing a lesson, module, and course together used to trigger three automations, but the system's double-enroll check was scoped wrong and silently dropped every automation after the first. Now each workflow is checked independently, and a genuinely skipped run is logged, not lost.
  2. Atomic tag / lead-score fix — two automations tagging or scoring the same contact within a fraction of a second could silently overwrite each other's work. Fixed with atomic database operations that can't race.
  3. RLS/permissions fix for webhook and cron-triggered automations — automations kicked off by a payment webhook or scheduled job weren't reliably able to write to the database under the same rules as user-triggered actions. Found and corrected.
  4. Anonymous access / middleware fix — real, logged-out visitors hitting public forms and funnels were being blocked by auth middleware. About as serious as a "form doesn't work" bug gets — caught and fixed here, not by a client's live traffic.
These were real bugs, found because we tested concurrent triggers, real anonymous traffic, and webhook/cron auth paths — not just the happy path. A system that's never had a bug found in it usually hasn't been pushed hard enough yet.
03

Honest gaps & in-progress items

WhatsApp templates aren't true templates yetIn progress

Sends a real WhatsApp message via Twilio, but as plain text rather than through Twilio's approved Content API template mechanism.

7 registered triggers fire nothingNot wired

Certificate issued/expiring, course expiring, student inactive, assignment submitted/graded, tag-confidence changed — defined as trigger types, but nothing in the product currently fires them.

A second automation engine exists for forms/funnelsSeparate system

"Engine B" runs public-form and funnel logic on its own infrastructure with its own trigger set (form submitted/viewed/abandoned, payment completed/failed) — separate code from the main Workflow Builder above. Unifying them is a reasonable next step.

No way to acknowledge a failed runMissing

A workflow-failure monitor exists but is disabled — the database has no column yet to mark a failure as handled.

"Create Task" isn't in the builder UI yetBackend only

The action works end-to-end but can't currently be added as a step from the visual editor.

05

Where this stands

This is a real, working automation engine, not a prototype — genuine multi-channel actions, live-data pickers, functioning branching, and a track record of concurrency and permissions bugs found and fixed under realistic conditions rather than a happy-path demo. Trigger and action breadth already covers the core CRM + LMS + payments use cases, and branching/entity-picker maturity is on par with Systeme.io and GHL.

Where it currently trails GHL specifically: native WhatsApp template sends and a dedicated execution-history UI — both scoped, known gaps rather than open questions. Systeme.io is generally the narrower product of the two, and LeadsMind's breadth already looks competitive or ahead of it in several areas verified here. This is a credible, production-tested system with a short, clearly bounded list of next steps.
